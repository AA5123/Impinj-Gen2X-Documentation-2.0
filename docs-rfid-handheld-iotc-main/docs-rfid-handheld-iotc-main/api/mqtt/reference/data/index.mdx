While an inventory runs, the reader publishes what it reads as [`dataEVT`](/api-reference/mqtt/data/tag-data-event): batches of tag records and barcode records. On a dedicated data endpoint, tag data arrives on `<tenantId>/DATA/clients/data1event/<deviceSerialNumber>`, from the [`DATA1`](/api-reference/mqtt/protocol-reference/connection-and-session#endpoint-types) endpoint's second publish topic. ([`DATA2`](/api-reference/mqtt/protocol-reference/connection-and-session#endpoint-types), with `data2event`, is currently not supported.) It is published at the QoS set on that topic, 0 or 1, is not retained, and is limited to 6144 bytes per message. The contract describes the stream as a statistical view of the tag population, not a guaranteed log of every read.

See [The Tag Data Stream](/guides/core-concepts/the-tag-data-stream).
