Values are case-sensitive and must be sent exactly as shown. Enumerations are closed: a schema validator rejects any other value. Where a note describes firmware support, the value is valid on the wire but current firmware reports it only in the places named.

| Value | Note |
| --- | --- |

### `mqttQoS` {#mqttQoS}

MQTT Quality of Service level. JSON type `integer`. Used by [`config_endpoint`](/api-reference/mqtt/mgmt/config-endpoint), [`get_endpoint_config`](/api-reference/mqtt/mgmt/get-endpoint-config).

The contract declares `qos` and `qosCommon` as integers without an enumeration or a default. MQTT 3.1.1 defines the levels `0`, `1` and `2`; the broker description states that the reader supports `0` and `1`. The contract's examples use `0` and `1`.

### `verificationType` {#verificationType}

TLS verification mode. JSON type `string`. Used by [`config_endpoint`](/api-reference/mqtt/mgmt/config-endpoint), [`get_endpoint_config`](/api-reference/mqtt/mgmt/get-endpoint-config), [`install_certificate`](/api-reference/mqtt/mgmt/install-certificate), [`set_os`](/api-reference/mqtt/mgmt/set-os).

This documentation describes two values:

| Value | Note |
| --- | --- |
| `VERIFY_HOST_AND_PEER` | Verify the broker's certificate chain and that the certificate matches the host. Use it in production. |
| `VERIFY_NONE` | No verification. Must not be used in production. An `MQTT_TLS` endpoint rejects it with [code `37`](/api-reference/mqtt/response-codes#code-37). |
