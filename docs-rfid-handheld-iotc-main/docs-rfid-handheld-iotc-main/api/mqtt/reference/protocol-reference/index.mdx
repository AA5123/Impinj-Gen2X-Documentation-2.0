These pages define the rules that every command and event follows. The operation pages under [Management](/api-reference/mqtt/management), [Control](/api-reference/mqtt/control), and [Events](/api-reference/mqtt/events) assume them.

## One Exchange, End to End {#one-exchange}

| Stage | What happens | Specified on |
| --- | --- | --- |
| Address | Your application builds the reader's command and response topics from the endpoint's configuration. | [Topics and Channels](/api-reference/mqtt/protocol-reference/topic-structure) |
| Subscribe | Your application subscribes to the response topic, and to the event topic if the command finishes asynchronously. | [Delivery and Retry Semantics](/api-reference/mqtt/protocol-reference/qos-and-delivery-semantics#retain) |
| Publish | Your application publishes a command envelope at [QoS 1](/api-reference/mqtt/protocol-reference/qos-and-delivery-semantics#qos). The broker's PUBACK means only that the broker received it. | [Message Envelopes and Correlation](/api-reference/mqtt/protocol-reference/message-envelope), [Delivery and Retry Semantics](/api-reference/mqtt/protocol-reference/qos-and-delivery-semantics) |
| Reply | The reader publishes one response with your [`requestId`](/api-reference/mqtt/protocol-reference/message-envelope#correlating-responses). Most commands finish with this reply; three acknowledge with [code `1`](/api-reference/mqtt/response-codes#code-1) and finish later. | [Message Envelopes and Correlation](/api-reference/mqtt/protocol-reference/message-envelope#correlation-and-request-response-pairing) |
| Outcome | Your application reads `response.code`, or waits for the event that reports the outcome. | [Response Codes](/api-reference/mqtt/response-codes) |
