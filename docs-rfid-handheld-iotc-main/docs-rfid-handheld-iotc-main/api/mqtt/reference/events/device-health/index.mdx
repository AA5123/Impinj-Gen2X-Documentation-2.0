The reader publishes [`heartBeatEVT`](/api-reference/mqtt/events/heartbeat-event) at the configured interval (at most 65,535 seconds) while the heartbeat is enabled with [`config_events`](/api-reference/mqtt/mgmt/config-events); a reboot applies the setting. Monitoring can rely on it as its primary liveness signal: when `heartBeatEVT` stops arriving, the reader, its session, or the path to your application needs attention. It is published at [QoS 0](/api-reference/mqtt/protocol-reference/qos-and-delivery-semantics#qos), so the MQTT layer does not resend one lost in transit; choose how many missed intervals your application treats as an outage. When enabled, it carries inventory and battery status.

See [Monitor Reader Health and Battery](/guides/operate-and-monitor/monitor-reader-health-and-battery).
