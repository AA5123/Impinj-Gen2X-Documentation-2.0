[`alerts`](/api-reference/mqtt/events/alerts-event) reports a condition change: battery, power, network, firmware update, file download or temperature, in `id`. Each alert carries a `priority` (`CRITICAL`, `HIGH` or `LOW`), a `state` (`SET`, `CLEAR` or `ONESHOT`) and a detail block matching its `id`. Alerts travel at [QoS 1](/api-reference/mqtt/protocol-reference/qos-and-delivery-semantics#qos), so the same one can arrive twice. The contract states no rule for which alerts latch until cleared.

See [Respond to Alerts](/guides/operate-and-monitor/respond-to-alerts).
