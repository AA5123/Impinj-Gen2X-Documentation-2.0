## Overview

`get_wifi` retrieves the **Wi-Fi profiles saved on the reader** together with their current connection status and configuration. The response is a list (`wifiProfiles.wifiConfig[]`) of profiles; each describes the wireless interface, the associated access point (ESSID, security type, connection status), the IPv4/IPv6 addressing, and a `securityDetails` block keyed by the security type (`WPA2Personal`, `WPA3Personal`, `WPA2Enterprise`, `WPA3Enterprise`). It is a read-only query on the device-management ([MGMT](/api-reference/mqtt/protocol-reference/connection-and-session#endpoint-types)) endpoint.

The device **masks** stored credentials — passwords, passphrases, and identities are returned as a mask, never the real secret. Use `get_wifi` to verify which SSID a reader is connected to and confirm its addressing before relying on the wireless uplink.

## When to Use

Use `get_wifi` when you need to **verify the reader's wireless configuration** — during commissioning, a connectivity check before inventory, or a fleet audit of which SSID each device is on.

- **Confirm the connection:** check `accessPoint.status` (CONNECTED?), `accessPoint.essid` (correct network?), and `accessPoint.isPreferred`.
- **Validate security:** check `accessPoint.securityType` matches the AP; the matching `securityDetails` block shows the (masked) credential/protocol configuration.
- **Validate addressing:** check `ipv4Configuration.ipAddress`, `gateway`, and `enableDhcp` to confirm the reader has a working route to the broker / back-end.

## Response Semantics

- **Credentials are masked.** The device returns stored passwords, passphrases, and identities as a mask (never the real secret). Treat every credential field in the response as opaque — you cannot read back the actual value with `get_wifi`.
- **Security type selects the credential block.** `securityDetails` contains only the one key that matches `accessPoint.securityType` — `WPA2Personal` / `WPA3Personal` (a single `password`) or `WPA2Enterprise` / `WPA3Enterprise` (EAP `authentication`, optional `innerAuthentication` / `identity` / `anonymousIdentity`, a `certificate` array, and a `protocol`).
- **`ipv6Configuration` is schema-defined but not returned by the current firmware.**
- **Wi-Fi-disabled response shape.** When Wi-Fi is disabled, the contract's own example returns the profile under a **top-level `wifiConfig`** object (rather than `wifiProfiles.wifiConfig[]`), carrying only `interfaceName`, `status` (`Disabled`), `hostname` and `macAddress`. The response schema does not declare a top-level `wifiConfig`, so parse both shapes; the connected shape documented here is `wifiProfiles.wifiConfig[]`.

## Notes and Caveats {#notes--caveats}

`get_wifi` is a read-only getter — safe to poll during commissioning or troubleshooting. Configure profiles with [`set_wifi`](/api-reference/mqtt/mgmt/set-wifi) / [`delete_wifi_profile`](/api-reference/mqtt/mgmt/delete-wifi-profile); for the concept-level view, see [Configure Wi-Fi](/guides/manage-your-reader/configure-wi-fi). Enterprise profiles depend on installed certificates — see [The Security Model](/guides/core-concepts/the-security-model).
