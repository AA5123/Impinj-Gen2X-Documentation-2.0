## Overview

`delete_certificate` **removes a certificate from the reader's trust store**, identified by `certificateInfo.{name, type}`. It is **synchronous** — a successful delete returns `response.code 0` and the certificate is gone immediately (confirm with [`get_installed_certificates`](/api-reference/mqtt/mgmt/get-installed-certificates)). It is a state-changing command on the device-management ([MGMT](/api-reference/mqtt/protocol-reference/connection-and-session#endpoint-types)) endpoint.

**`delete_certificate` is destructive and irreversible — and omitting `certificateInfo.name` deletes every certificate of the given `type`.** See the danger callout in [Notes and Caveats](#notes--caveats) before sending.

## When to Use

Use `delete_certificate` to **clean up the reader's trust store**:

- **Remove an obsolete or expired certificate** — e.g. before rotating in a replacement.
- **Clear a slot before re-installing** — delete then [`install_certificate`](/api-reference/mqtt/mgmt/install-certificate) with the same `name`.
- **Wipe a whole type** — omit `name` to remove every certificate of a `type` (e.g. all `wifi` certificates) in one call. Use deliberately.

Delete only certificates that are **not in active use**. On a TLS endpoint, deleting the broker/client certificate the reader is currently connected with will break that connection.

## Request Semantics

- **`certificateInfo` is required, and so is the `type` inside it.** The contract requires the payload outright, and the device agrees — a request without it is rejected with [code `101`](/api-reference/mqtt/response-codes#code-101). Always send `certificateInfo` with at least a valid `type`.
- **Type-`null` certificates cannot be deleted.** `delete_certificate` matches on `type`, so a certificate that [`install_certificate`](/api-reference/mqtt/mgmt/install-certificate) created **without a `type`** (`type: null`, which the installer accepts) matches no `type` value and returns [code `21`](/api-reference/mqtt/response-codes#code-21) for every attempt — it becomes un-deletable through this command. Avoid the situation by always sending `type` to `install_certificate`; to clear an existing orphan, re-install the same `name` with an explicit `type`.

The codes applicable to this command are below; for the full table see the [Response Codes](/api-reference/mqtt/response-codes) and [Correlation and Request/Response Pairing](/api-reference/mqtt/protocol-reference/message-envelope#correlation-and-request-response-pairing).

| Code | Description |
| --- | --- |
| `0` | Success — the matching certificate (or all of the type) was removed. |
| `9` | File not found (`IOT_STATUS_FILE_NOT_FOUND`) — a backing certificate file could not be found. |
| `21` | Certificate not found (`IOT_ERROR_CERT_NOT_FOUND`) — the `name`/`type` is not a saved certificate. See the not-found note below. |
| `101` | Default error — generic catch-all (e.g. a malformed payload; see the note below). |

Two live-observed behaviors to code against: (1) **A not-found delete returns [code `21`](/api-reference/mqtt/response-codes#code-21) but with the description text `"File not found"`** (the wording of [code `9`](/api-reference/mqtt/response-codes#code-9)) — key on the numeric `21`, not the string. (2) A **malformed payload** — a missing required `type`, or a missing `certificateInfo` — returns the generic **`101`** ("Default error"), while an **invalid `type`** value returns **`23`** ("Invalid enum value"). Gate success strictly on `code == 0`.

## Notes and Caveats {#notes--caveats}

:::caution[Irreversible — and omitting `name` wipes every certificate of the type]
**There is no undo and no confirmation prompt.** A `delete_certificate` with `certificateInfo.type` but no `name` deletes **every** certificate of that type. Always include an explicit `name` unless a full type-wipe is intended, and verify the exact name first with [`get_installed_certificates`](/api-reference/mqtt/mgmt/get-installed-certificates). Never delete a certificate an **active TLS connection** relies on — doing so breaks that connection. Recovery in every case means re-installing with [`install_certificate`](/api-reference/mqtt/mgmt/install-certificate).
:::

Because the response is status-only, **verify the result with [`get_installed_certificates`](/api-reference/mqtt/mgmt/get-installed-certificates)** — confirm the deleted `name`/`type` no longer appears.
