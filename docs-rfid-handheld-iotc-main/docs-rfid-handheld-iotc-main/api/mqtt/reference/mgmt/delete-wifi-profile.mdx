## Overview

`delete_wifi_profile` **permanently removes a single saved Wi-Fi profile** from the reader's profile store. The profile is identified by its `essid` inside `wifiProfileInfo`; on success the matching saved profile — including any stored credentials — is deleted, and the command returns a status-only envelope (no profile echo). It is a state-changing command on the device-management ([MGMT](/api-reference/mqtt/protocol-reference/connection-and-session#endpoint-types)) endpoint. Confirm the result with [`get_wifi`](/api-reference/mqtt/mgmt/get-wifi).

**Deletion is permanent** — there is no "undelete"; restoring a profile means re-provisioning with [`set_wifi`](/api-reference/mqtt/mgmt/set-wifi). The deletion is safe for the control session: the reader refuses to delete the active profile ([code `16`](/api-reference/mqtt/response-codes#code-16)). See [Notes and Caveats](#notes--caveats).

## When to Use

Use `delete_wifi_profile` to **clean up the reader's saved Wi-Fi profiles** — one profile per call, matched by `essid`.

- **Remove an obsolete or incorrect profile** — e.g. a network that no longer exists, or one saved with the wrong credentials.
- **Make room before adding a profile** — the device enforces a maximum number of saved profiles; if [`set_wifi`](/api-reference/mqtt/mgmt/set-wifi) `CREATE` returns [code `19`](/api-reference/mqtt/response-codes#code-19) (SSID count overflow), delete an unused profile first.
- **Tidy fallback sets** — prune stale entries so the reader only carries the profiles you intend it to roam across.

Delete only a **non-active** profile. To retire the network the reader is currently connected to, first connect it elsewhere (with `set_wifi` `connect: true`) — the device will not delete the profile carrying its live connection ([code `16`](/api-reference/mqtt/response-codes#code-16)).

## Request Semantics

- **One profile per call, matched by `essid`.** `delete_wifi_profile` removes a single saved profile identified by its network name. A [`code 15`](/api-reference/mqtt/response-codes#code-15) means the `essid` is not saved (typo or wrong case); confirm the exact stored name with [`get_wifi`](/api-reference/mqtt/mgmt/get-wifi) first. ## Notes and Caveats {#notes--caveats}

:::caution[Deletion is permanent]
There is no undo. The saved profile and its stored credentials are removed; restoring it means re-provisioning with [`set_wifi`](/api-reference/mqtt/mgmt/set-wifi) and re-entering the credentials. Double-check the `essid` before sending — the match is **case-sensitive** and exact.
:::

- **The active profile is firmware-protected.** Unlike [`set_wifi`](/api-reference/mqtt/mgmt/set-wifi) with `connect: true` — which can switch networks and sever the control session — `delete_wifi_profile` **cannot** strand the reader: if you target the currently-connected `essid`, the device refuses with [code `16`](/api-reference/mqtt/response-codes#code-16) ("Cannot delete active SSID") rather than dropping its own connection. To retire the network the reader manages itself over, first move it to another profile (`set_wifi` `connect: true`), then delete the now-inactive profile.

Because the response is status-only, **verify the result with [`get_wifi`](/api-reference/mqtt/mgmt/get-wifi)** — confirm the deleted `essid` no longer appears in the saved profiles and the connected profile is unchanged.
