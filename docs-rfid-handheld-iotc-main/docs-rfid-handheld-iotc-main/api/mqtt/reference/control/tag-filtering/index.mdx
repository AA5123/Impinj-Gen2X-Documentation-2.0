Post-filter rules decide which read tags a data endpoint reports: `DATA_EP1` for the [`DATA1`](/api-reference/mqtt/protocol-reference/connection-and-session#endpoint-types) endpoint. (`DATA_EP2` targets [`DATA2`](/api-reference/mqtt/protocol-reference/connection-and-session#endpoint-types), which is currently not supported.) [`set_post_filter`](/api-reference/mqtt/ctrl/set-post-filter) adds, modifies or deletes one rule per request (a delete names only the data endpoint), matching the tag ID by `PREFIX`, `SUFFIX` or `REGEX`, and including or excluding what matches. [`get_post_filter`](/api-reference/mqtt/ctrl/get-post-filter) returns the installed rules and is safe to send again. Pre-filters, which act on the air, are part of the [operating mode](/api-reference/mqtt/ctrl/set-operating-mode).

See [Post-Filter Reported Tags](/guides/read-tags-and-barcodes/post-filter-reported-tags).
