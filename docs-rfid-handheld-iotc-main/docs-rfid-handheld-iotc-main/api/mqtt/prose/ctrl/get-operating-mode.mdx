## Overview

`get_operating_mode` **reads back the reader's current RFID operating-mode configuration** — the active profile, radio start/stop conditions, Gen2 `query` parameters, select pre-filters, armed access operations, and tag-metadata reporting flags — under `operatingMode.operatingModes`. It is read-only. It is a **control-plane ([CTRL](/api-reference/mqtt/protocol-reference/connection-and-session#endpoint-types)) command** — configure the mode with [`set_operating_mode`](/api-reference/mqtt/ctrl/set-operating-mode).

This is a **CTRL-endpoint command**: it is published on the **control** endpoint (`<tenantId>/CTRL/clients/cmnd/<serial>`) and answered only there (not on the [MGMT](/api-reference/mqtt/protocol-reference/connection-and-session#endpoint-types)/[MDM](/api-reference/mqtt/protocol-reference/connection-and-session#endpoint-types) channel). Returning a response requires an **active CTRL endpoint** (configured with [`config_endpoint`](/api-reference/mqtt/mgmt/config-endpoint), `epType: CTRL`, `activate: true`). See [Topic Mapping](#topic-mapping).

## When to Use

Use `get_operating_mode` to **inspect or audit the reader's RFID configuration**:

- **Before an inventory** — confirm the profile, `query` parameters, and trigger conditions are what you expect.
- **After [`set_operating_mode`](/api-reference/mqtt/ctrl/set-operating-mode)** — verify the mode was applied (there is no configuration echo on the set command's response).
- **After a reboot** — the operating mode reverts to default on reboot (see the volatility note); read it back to confirm the current state.
- **Check reporting** — see which `tagMetaDataToEnable` fields the reader will include on tag reads.

Topics follow the pattern `<tenantId>/<topic>/<serial>` — the tenant id assigned to you at provisioning (a slot you fill in, never a literal), the base topic you configure on the endpoint, and the reader's serial number, which the reader appends itself in its model-prefixed form (for example `RFD40-212735201D0053`). `App → Reader` means your app publishes and the reader subscribes; `Reader → App` means the reader publishes and your app subscribes.

Unlike the MGMT commands, control commands are answered **only on the CTRL endpoint** — publishing `get_operating_mode` to the MGMT/MDM command topic produces no reply.

If no CTRL endpoint is active, add or activate one with [`config_endpoint`](/api-reference/mqtt/mgmt/config-endpoint) (`epType: CTRL`, `activate: true`) before sending control commands. The `requestId` you send is echoed in the response.

## Key Fields

- **`operatingMode.operatingModes.profiles`** (response) — the active profile (e.g. `BALANCED_PERFORMANCE`); `ADVANCED` surfaces `advancedConfigurations`.
- **`query`** (response) — the Gen2 session / inventory-state / SL-flag / tag-population parameters driving inventory.
- **`radioStartConditions` / `radioStopConditions`** (response) — the trigger semantics for starting/stopping inventory.
- **`tagMetaDataToEnable`** (response) — which metadata fields (RSSI, EPC, TID, …) the reader reports on each tag read.
- **`response.code`** (response) — read this to determine success vs failure. The contract requires it; note the reported success-path omission. See [Response Codes](#response-codes).

## Response Semantics

- **The read-back masks access passwords.** When access operations are armed, `get_operating_mode` returns their structure but echoes `config.password` as empty (`""`) — the stored credential is never returned. The real password is carried only in the [`set_operating_mode`](/api-reference/mqtt/ctrl/set-operating-mode) request (mask it there). A default read-back has no `accessOperations` at all.
- **`FAST_READ` is enumerated but not supported.** The `profiles` enum lists `FAST_READ`, but it is **currently not supported** by the firmware (per the schema's own description). Use `CYCLE_COUNT`, `DENSE_READERS`, `OPTIMAL_BATTERY`, `BALANCED_PERFORMANCE`, or `ADVANCED`.
- **Conditional sub-objects.** `advancedConfigurations` appears only when `profiles` is `ADVANCED`; `accessOperations` and `select` appear only when configured. A default read-back typically returns just `profiles`, `inventoryProtocol`, `radioStartConditions`, `radioStopConditions`, `query`, and `tagMetaDataToEnable`.

## Response Codes

`get_operating_mode` returns `response.code`. The codes applicable to this command are below; for the full table see the [Response Codes](/api-reference/mqtt/response-codes) and [Correlation and Request/Response Pairing](/api-reference/mqtt/protocol-reference/message-envelope#correlation-and-request-response-pairing).

| Code | Description |
| --- | --- |
| `0` | Success — the operating mode was retrieved. |
| `3` | Not able to retrieve information (`IOT_ERROR_INFO_NOT_AVAILABLE`) — the device could not gather the operating mode at this time. Retry after a short delay; if persistent, reboot. |
| `101` | Default error — generic catch-all. |

The contract requires `response.code`; readers have been reported to omit it on success — see [Success without a code](/api-reference/mqtt/protocol-reference/message-envelope#success-omits-code).

## Examples

Publish `get_operating_mode` over the CTRL endpoint (with an active CTRL endpoint); the device replies with the snapshot shown under [Response Payload](#response-payload). There are no request variants — the command takes no parameters.

## Notes and Caveats {#notes--caveats}

- **Operating mode is volatile.** The operating mode resets to default (`BALANCED_PERFORMANCE`, armed `accessOperations` cleared) on [`reboot`](/api-reference/mqtt/mgmt/reboot). Read it back after a reset to confirm the current state; re-apply with [`set_operating_mode`](/api-reference/mqtt/ctrl/set-operating-mode) if you were relying on a non-default configuration.

Read `get_operating_mode` to confirm the reader's RF configuration before running an inventory with [`control_operation`](/api-reference/mqtt/ctrl/control-operation), and to verify a change applied by [`set_operating_mode`](/api-reference/mqtt/ctrl/set-operating-mode). For the concept-level view, see [Choose an Operating Mode](/guides/read-tags-and-barcodes/choose-a-performance-profile#choose-an-operating-mode).
