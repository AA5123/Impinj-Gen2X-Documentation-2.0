> 📕 **REFERENCE** · **Audience:** API consumer · **Use:** list the certificates installed in the reader's trust store

## Overview

`get_installed_certificates` **lists the certificates in the reader's trust store**, returning per-certificate **metadata** — name, type, issuer/subject, serial, public-key algorithm, and validity dates — under `installedCerts.certInfo[]`. It is read-only and returns **no private-key material**. Use it to audit the certificate inventory and to confirm a certificate exists (and is valid) before referencing it from [`config_endpoint`](/api-reference/mqtt/mgmt/config-endpoint) or [`set_wifi`](/api-reference/mqtt/mgmt/set-wifi).

## When to Use

Use `get_installed_certificates` to **audit or verify the reader's certificate inventory**:

- **Before configuring TLS** — confirm the `ca_cert` / `client_cert` referenced by [`config_endpoint`](/api-reference/mqtt/mgmt/config-endpoint) (`MQTT_TLS`) or [`set_wifi`](/api-reference/mqtt/mgmt/set-wifi) (Enterprise) is installed and of the right `type`.
- **Rotation planning** — check `validTill` (expiry) and `validFrom` (not-yet-valid) to schedule renewals before TLS handshakes start failing.
- **Trust audit** — review `issuerName` / `subjectName` / `serial` to confirm the expected CA chain.

## Key Fields

- **`certInfo[].type`** (response) — the certificate's scope (`mqtt`, `wifi`, `filestore`, `client`, `server`); a certificate installed for one type is not usable by another.
- **`certInfo[].name`** (response) — the certificate's name. Published examples show component identifiers (`ca_cert`, `client_cert`), not the logical name given to [`install_certificate`](/api-reference/mqtt/mgmt/install-certificate); which the reader reports is unresolved.
- **`certInfo[].validTill` / `validFrom`** (response) — the validity window; an expired or not-yet-valid certificate causes TLS handshake failures.
- **`certInfo[].issuerName` / `subjectName` / `serial`** (response) — identify the certificate and its CA chain (note `serial` is truncated — see [Response Semantics](#response-semantics)).
- **`response.code`** (response) — read this to determine success vs failure (see [Response Codes](#response-codes)).

## Response Semantics

- **`serial` is truncated to 8 bytes.** The device returns the certificate serial as colon-delimited hex, but only the **first 8 bytes** of the (typically 20-byte) real serial — e.g. `7d:ef:d4:c3:2d:39:4a:0b`. Combine `serial` with `name` + `type` + `issuerName` to identify a certificate uniquely; `serial` alone is not a globally unique identifier.
- **Private keys are never listed.** The inventory returns public certificate metadata only. A `client_key` installed via [`install_certificate`](/api-reference/mqtt/mgmt/install-certificate) does **not** appear in `certInfo[]` — only its paired `ca_cert` / `client_cert` do. There is no way (by design) to read back private-key material.
- **`publicKey` and `publicKeyAlg` quirks.** The device currently populates `publicKey` with the algorithm name (e.g. `RSA`) rather than actual key bytes — treat `publicKey` as informational, not as usable key material. `publicKeyAlg` reports the certificate's public-key algorithm — an `RSA` variant (see the allowed values under [Response Payload](#response-payload)).

## Response Codes

`get_installed_certificates` returns `response.code`. The codes applicable to this command are below; for the full table see the [Response Codes](/api-reference/mqtt/response-codes) and [Correlation and Request/Response Pairing](/api-reference/mqtt/protocol-reference/message-envelope#correlation-and-request-response-pairing).

| Code | Description |
| --- | --- |
| `0` | Success — the inventory was retrieved (an empty trust store still returns `0` with an empty/absent `certInfo`). |
| `3` | Not able to retrieve information (`IOT_ERROR_INFO_NOT_AVAILABLE`) — the device could not gather the certificate list at this time. Retry after a short delay; if persistent, reboot. |
| `9` | File not found (`IOT_STATUS_FILE_NOT_FOUND`) — a backing certificate file could not be found. |
| `21` | Certificate not found (`IOT_ERROR_CERT_NOT_FOUND`) — the requested certificate is not installed. |
| `101` | Default error — generic catch-all. |

[Codes `3`](/api-reference/mqtt/response-codes#code-3) / `9` / `21` are this command's mapped failure codes. The request takes no parameters; send exactly `command` + `requestId`.

## Examples

Publish the plural `get_installed_certificates` with a `requestId`; the device replies with the inventory shown under [Response Payload](#response-payload). The command always returns the full list and takes no parameters (there are no request variants).

## Notes and Caveats {#notes--caveats}

**Read-only, but still sensitive.** The inventory exposes no secrets (no private keys), but a certificate list reveals the device's PKI/trust topology — redact it in shared logs, tickets, and screenshots.
