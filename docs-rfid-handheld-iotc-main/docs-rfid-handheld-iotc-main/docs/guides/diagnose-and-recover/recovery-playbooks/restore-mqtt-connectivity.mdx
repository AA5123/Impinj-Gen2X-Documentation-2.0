Two playbooks for the control plane. The reader is powered and on the network, but the MQTT path between you and it is not carrying anything. Either the endpoint that should be speaking is not active (RP-02), or it is active and you are publishing to — or listening on — the wrong topic (RP-03).

Run each step; verify the success check; move on.

### RP-02: Activate the Bootstrap MDM Endpoint {#rp-02}

**When:** The reader was bootstrapped, but no MQTT command works.

1. Open 123RFID Desktop and connect to the reader over USB-C.
2. In the **End Point** tab, find the MDM endpoint and confirm that it is activated.
3. Check that its broker URL, port and protocol match a broker the reader's network can reach, and that the protocol matches the port.
4. Correct and activate the endpoint. See [Bootstrap a Reader with 123RFID Desktop](/guides/manage-your-reader/bootstrap-reader).
5. Watch the broker's log for an incoming connection from the reader.
6. **Success check:** subscribe to `<tenantId>/MDM/#` and see a `CONNECTED` `mqttConnEVT`, or any other message, from the reader.

### RP-03: Verify Topic Routing {#rp-03}

**When:** [`get_version`](/api-reference/mqtt/mgmt/get-version), or any command, gets no reply within your timeout.

1. Check the command topic segment by segment: the tenant ID, the endpoint's subscribe-topic middle segment, and the serial number in the form the reader uses. Topics are case-sensitive, and a mismatch fails silently.
2. On a test broker, subscribe to the tenant's topics with a wildcard, for example `mosquitto_sub -t '<tenantId>/#' -v`, and publish the command again.
3. Find which topic the response arrives on. Update your subscriber to use that exact topic.
4. If a reply arrives anywhere, run [`get_endpoint_config`](/api-reference/mqtt/mgmt/get-endpoint-config) and check the endpoint's `subscribeTopics` and `publishTopics`; replies go to `publishTopics[0]`.
5. **Success check:** `get_version` replies on the topic you subscribe to, echoing your `requestId`.
