**Scope.** The reader and its firmware: power and battery, the radio, firmware updates, restarts and identity. These faults are cleared at the reader: by charging it, restarting it, updating its firmware or replacing it.

If the reader is healthy but cannot reach the network, start at [Network and Connectivity](/guides/diagnose-and-recover/diagnose-by-system-area/network-and-connectivity) instead. If it reaches the network but not the broker, start at [MQTT Connection](/guides/diagnose-and-recover/diagnose-by-system-area/mqtt-connection).

## First Command

[`get_status`](/api-reference/mqtt/mgmt/get-status) answers every question in this area at once — `powerSource`, `radioActivity`, `radioConnection`, `systemTime`, `temperature`, and the `batteryStatus` block. Run it before you form a hypothesis. If it does not answer at all, the fault is not in this area; it is on the path.

## Power and Battery

Battery state gates more than runtime: a firmware update is refused when the battery is too low ([FM-FW-04](/guides/diagnose-and-recover/diagnose-by-system-area#fm-fw-04)). When you are diagnosing anything else, keep the reader on external power so that power is not a hidden variable. `get_status` reports the source as `powerSource`.

`get_status.deviceStatus.batteryStatus` gives you `chargePercentage`, `chargeStatus`, `capacity`, and `stateOfHealth`. For trends across a shift or a fleet rather than a single reading, use the [battery-monitoring guide](/guides/operate-and-monitor/monitor-reader-health-and-battery#battery-health).

## Radio Faults {#radio-faults}

The contract describes `radioConnection` in [`get_status`](/api-reference/mqtt/mgmt/get-status) as whether the RFID radio module is attached and reachable, yet its own example replies show `DISCONNECTED` on an idle reader, so do not treat that value as a fault on its own. If an inventory will not start, or a command returns code `3` (`IOT_ERROR_INFO_NOT_AVAILABLE`) persistently, the contract's recommended action is to retry after a short delay and, if it persists, reboot the reader. If the problem returns on the same reader after a reboot, contact Zebra support.

`radioActivity: ACTIVE` is not a fault — but it blocks [`set_operating_mode`](/api-reference/mqtt/ctrl/set-operating-mode) and [`reboot`](/api-reference/mqtt/mgmt/reboot). Clear it with [RP-04](/guides/diagnose-and-recover/recovery-playbooks/recover-from-configuration-problems#rp-04) before concluding anything else.
