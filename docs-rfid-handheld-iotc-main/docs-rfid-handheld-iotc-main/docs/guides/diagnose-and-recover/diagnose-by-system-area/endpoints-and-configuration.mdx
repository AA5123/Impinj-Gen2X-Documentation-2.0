**Scope.** What the reader has been told to be: endpoint definitions, topic lists, event-reporting flags, operating-mode payloads, and configuration that has drifted from your baseline or was reset by a restart.

The signature of this area is that the reader **answers** — commands get replies — but the replies carry a rejection code, or the configuration you expect is not the configuration you get. If nothing answers at all, start at [MQTT Connection](/guides/diagnose-and-recover/diagnose-by-system-area/mqtt-connection).

## First Command

[`get_endpoint_config`](/api-reference/mqtt/mgmt/get-endpoint-config) returns the whole endpoint picture in one reply: which endpoints are saved, which are `activate: true`, their `protocol`, `url`, `port`, `verificationType`, their publish and subscribe topics, and each one's `eventConfiguration`. Compare it against what you believe you pushed before changing anything.

## Two Rules That Explain Most of These

**A restart resets the operating mode.** The contract states that the settings made with [`set_operating_mode`](/api-reference/mqtt/ctrl/set-operating-mode) are lost on reboot. Re-apply them as part of your startup sequence rather than treating their absence as a fault. Whether other domains survive a restart is not specified in the available sources.

**The limits are low and they are hard.** Three publish topics and one subscribe topic per endpoint, 32 select pre-filters, a 15-character endpoint name and a 48-character tenant ID. The maximum number of Wi-Fi profiles is not stated; code `19` reports it. A design that needs more capacity needs more endpoints, not a larger array — see [FM-CFG-02](/guides/diagnose-and-recover/diagnose-by-system-area#fm-cfg-02) and [Response Codes](/api-reference/mqtt/response-codes) for the full set.

## Changes That Need a Reboot

Event-reporting changes made with [`config_events`](/api-reference/mqtt/mgmt/config-events) take effect only after the reader reboots. If heartbeats or alerts you enabled do not arrive, confirm that the reader restarted after the change before you send it again. An endpoint change is refused with code `35` while the endpoint is active; see [Configure MQTT Endpoints](/guides/manage-your-reader/configure-mqtt-endpoints#update).
