**Applies when:** the reader answers commands, but `heartBeatEVT`, `alerts` or `mqttConnEVT` never reach your application.

Work through the checks in order, and stop at the first one that fails.

1. **Is the event enabled, and has the reader restarted since?** `heartBeatEVT` and `alerts` are enabled with [`config_events`](/api-reference/mqtt/mgmt/config-events), and a change takes effect only after a reboot. Check the `eventConfiguration` block in [`get_endpoint_config`](/api-reference/mqtt/mgmt/get-endpoint-config); if you are unsure, send the settings again and restart the reader. See [Configure Event Reporting](/guides/operate-and-monitor/configure-event-reporting).
2. **Is the flag one the firmware supports?** On v1.1 only `heartbeat`, `battery`, `power`, `network`, `firmwareUpdate`, `fileDownload` and `terminalConnection` have an effect. The others are reserved. See [What the Event Flags Do Not Produce](/guides/operate-and-monitor/what-to-monitor-and-why#what-is-not-currently-emitted).
3. **Does the endpoint have a second publish topic?** `heartBeatEVT` and `alerts` go to `publishTopics[1]`. On a `CTRL` endpoint that slot is stored but not used for events. Check with [`get_endpoint_config`](/api-reference/mqtt/mgmt/get-endpoint-config).
4. **Is it an `MGMT_EVT` endpoint?** Such an endpoint currently publishes its events on its subscribe topic instead of slot 1, which the API owners record as a firmware defect. Subscribe to that topic.
5. **Are you watching the right topic?** `mqttConnEVT` and the Last Will go to the connection-state topic, `publishTopics[2]`, not the event topic, and no `config_events` flag controls them. See [FM-EVT-01](/guides/diagnose-and-recover/diagnose-by-system-area#fm-evt-01).
6. **For the heartbeat, have you waited a whole interval?** The interval is at most 65,535 seconds. `heartBeatEVT` travels at QoS 0, so a single one can be lost.
7. **Did you subscribe before the event?** Events are not reliably retained; one published before your subscription was active is lost.

**If none apply:** collect the evidence in [Escalate to Support](/guides/diagnose-and-recover/escalate-to-support).
