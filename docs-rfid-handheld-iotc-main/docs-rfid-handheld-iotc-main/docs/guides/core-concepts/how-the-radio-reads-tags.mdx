[MQTT in the IoT Connector](/guides/core-concepts/mqtt-in-the-iot-connector) explains how IOTC *transports* data; this page explains what that data *is* at the radio layer. Everything a reader streams as `dataEVT` originates here.

RFID is **radio-frequency identification**: a reader detects tags over the air, with no line of sight and no contact. Zebra handheld sleds (RFD40 / RFD90) use **UHF passive RFID** on the **EPC Gen2** standard (EPCglobal UHF Gen2v2), standardized as **ISO/IEC 18000-63**. The four ideas below are enough to read the rest of these docs; the sections after them cover the mechanics those ideas rest on — singulation, sessions, and memory banks. If you have built UHF RFID systems before, start at *Inventory Rounds and the Q Parameter*.

### 1. Passive Tags Have No Battery

A UHF tag is just an antenna and a tiny chip — no power source. The reader transmits RF energy; the tag *harvests* that energy to power its chip, then answers by **backscattering** — reflecting a modulated version of the reader's own signal.

```d2
direction: right
reader: "Handheld reader" { shape: rectangle }
tag: "Passive tag (no battery)" { shape: rectangle }
reader -> tag: "RF energy powers the tag"
tag -> reader: "backscattered EPC reply" { style.stroke-dash: 4 }
```

Two consequences follow from this asymmetry: range is short, and the tag's reply is a faint echo that the reader has to work to hear.

### 2. A Read Is Probabilistic, Not a Lookup

Coming from software, you might expect "scan = return all tags." RFID is not deterministic like that. Whether a given tag answers in a given instant depends on its orientation, distance, antenna null spots, and interference from other tags and readers. Readers compensate by reading **continuously**, so the same tag is usually read many times. Each `dataEVT` can carry several tag records, and a record's `seenCount` says how many times that tag was read since it was last reported. See [`dataEVT`](/api-reference/mqtt/data/tag-data-event).

### 3. Singulation Reads One Tag out of Many

Energize a box of tags and they would all reply at once and collide — their backscatter cannot share the air. **Singulation** is the anti-collision process that isolates one tag at a time so the reader can read it cleanly. The reader sweeps the field over and over in repeated *inventory rounds*, emitting a read each time it cleanly hears a single tag.

### 4. The EPC Is the Tag Identifier {#4-the-epc-is-the-tags-identifier}

Each tag carries an **EPC** (Electronic Product Code) — a hex string held in the tag's EPC memory bank, often a GS1 encoding (such as SGTIN) of a product plus a serial number. Most applications treat the EPC as an opaque key and look it up in a database; decoding its GS1 structure matters only when you reason about company prefix or item reference. Tags also expose other memory banks (TID, USER), covered further down this page.

### Inventory Rounds and the Q Parameter

Gen2 resolves the collision problem with a slotted **anti-collision** scheme. The reader opens an *inventory round* with a `Query` that carries a value **`Q`**; each tag picks a random slot in the range 0 to 2^Q − 1. The reader then steps through the slots:

```d2
direction: down
q: "Query: reader sets Q (2^Q slots)"
slot: "each tag picks a random slot"
read: "slot with one tag -> ACK -> read EPC"
again: "empty or collided slots -> next round"
q -> slot
slot -> read
slot -> again
again -> q: "adjust Q, repeat" { style.stroke-dash: 4 }
```

A slot holding exactly one tag is read cleanly; empty and collided slots are skipped, and the reader raises or lowers `Q` to match the tag population (dynamic Q). The key takeaway for application authors: a **single sweep does not catch every tag**. The reader runs many rounds per second, which is precisely why reads are probabilistic and why `dataEVT` carries a `seenCount`.

### Sessions and the Inventoried Flag

Each tag keeps an **inventoried flag** (state `A` or `B`) for each of four **sessions**, `S0`–`S3`. In the MQTT API the session is `query.session` in the operating mode, with the values `SESSION_0` to `SESSION_3`. After the reader reads a tag, it flips that tag's flag so the tag is not re-counted within the same round. The sessions differ only in **how long the flag persists** once the tag leaves the field:

The persistence times below are typical EPC Gen2 behavior, not values the MQTT API states.

| Session | Flag persistence | Typical use |
|---|---|---|
| `S0` | None (resets immediately) | Single reader, short continuous sweeps |
| `S1` | ~0.5–5 s | Most multi-round inventories |
| `S2` | Seconds and longer | Multi-reader environments |
| `S3` | Longest, until the reader resets it | Multi-reader with strict de-duplication |

Sessions are what let several readers cover the same area without each one constantly re-reading the others' tags. Choosing one for a deployment is covered in [Choose an Operating Mode](/guides/read-tags-and-barcodes/choose-a-performance-profile#choose-an-operating-mode).

### SELECT: Filtering Before the Round

Before an inventory round, the reader can issue a Gen2 **`SELECT`** that asserts or de-asserts a flag on every tag whose memory matches a bit mask — so only the matching subset takes part in the round. This is **pre-filtering**, and it is distinct from the post-singulation report filters applied after a tag is read. The trade-off between the two is the subject of [Pre-Filter Tags with Select](/guides/read-tags-and-barcodes/pre-filter-tags-with-select) and [Post-Filter Reported Tags](/guides/read-tags-and-barcodes/post-filter-reported-tags).

### The Four Memory Banks

Every Gen2 tag exposes four memory banks:

- **RESERVED** (bank 0) — the kill and access passwords.
- **EPC** (bank 1) — the identifier (protocol-control bits, the EPC, and a CRC). Writable.
- **TID** (bank 2) — the factory-programmed tag and chip identity. Read-only.
- **USER** (bank 3) — optional application-writable data.

For the precise read / write / lock matrix and the access operations (`READ`, `WRITE`, `ACCESS`, `LOCK`, `KILL`) with their password and length constraints, see [Tag and EPC Standards](/resources/tag-and-epc-standards).

### What Reaches Your Application

The reader turns each clean singulation into a `dataEVT` carrying the EPC plus optional metadata — **RSSI** (signal strength in dBm, a rough proximity hint), **phase**, channel, seen count, and (when enabled) TID or USER data. An application can use those values to reason about *which* tag is closest, but EPC Gen2 has no built-in "find this one tag" command — any locate behavior is built application-side on top of RSSI. The mapping from air interface to event is in [The Tag Data Stream](/guides/core-concepts/the-tag-data-stream), and field-level interpretation in [`dataEVT`](/api-reference/mqtt/data/tag-data-event).

### The Handheld Shape

A handheld reader starts and stops an inventory on triggers you configure with [`set_operating_mode`](/api-reference/mqtt/ctrl/set-operating-mode): `PRESSED` and `RELEASED` follow the handheld trigger, and `IMMEDIATE` acts without any trigger action. [`control_operation`](/api-reference/mqtt/ctrl/control-operation) starts and stops the inventory over MQTT. It also runs on a battery, which is why the MQTT API offers operating-mode *profiles* that trade read rate against battery life and interference — see [Choose an Operating Mode](/guides/read-tags-and-barcodes/choose-a-performance-profile#choose-an-operating-mode).

### Frequencies and Region

UHF Gen2 operates in the 860–960 MHz band, bounded by region — for example FCC 902–928 MHz, ETSI 865–868 MHz — and the region also caps transmit power. A reader's region is set at bootstrap with 123RFID Desktop, **not** over MQTT; the bands and limits are in [RF Regions and Regulations](/resources/rf-regions-and-regulations).
