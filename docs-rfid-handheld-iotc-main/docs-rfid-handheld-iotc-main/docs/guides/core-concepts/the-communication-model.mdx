The reader, the broker and your application never talk to each other directly: every message goes through the broker, on a topic, and your application pairs replies with requests by their `requestId`. Read these pages in order the first time:

1. [How the IoT Connector Works](/guides/core-concepts/how-the-iot-connector-works): the parts and the life of a message.
2. [MQTT in the IoT Connector](/guides/core-concepts/mqtt-in-the-iot-connector): the MQTT 3.1.1 ideas the API relies on.
3. [Endpoints, Topics, and Channels](/guides/core-concepts/endpoints-topics-and-channels): how the reader builds each topic, and why the position of a publish topic matters.
4. [Commands, Responses, and Events](/guides/core-concepts/commands-responses-and-events): the three flows of messages.
5. [Delivery, Retries, and Disconnects](/guides/core-concepts/delivery-retries-and-disconnects): what is guaranteed, what is not, and what your application can know.
6. [The Security Model](/guides/core-concepts/the-security-model): how the connection is protected.
