The MQTT API works on one reader at a time: there is no fleet command and no command that reads or writes a whole configuration. Running many readers therefore means tooling that repeats per-reader, per-domain commands, and practices that keep the fleet consistent and safe to change.

1. [What Changes When You Scale](/guides/scale-to-a-fleet/what-changes-when-you-scale): bootstrap, topics, tenancy and consistency with many readers.
2. [Provision Readers](/guides/scale-to-a-fleet/provision-readers): bootstrap each reader, then apply a baseline over MQTT.
3. [Keep Configuration Consistent](/guides/scale-to-a-fleet/keep-configuration-consistent): find and correct drift from the baseline.
4. [Roll Out Changes in Stages](/guides/scale-to-a-fleet/roll-out-changes-in-stages): firmware and configuration changes, a few readers at a time.

Watching a fleet in service is covered in [Build a Fleet Health View](/guides/operate-and-monitor/build-a-fleet-health-view).
