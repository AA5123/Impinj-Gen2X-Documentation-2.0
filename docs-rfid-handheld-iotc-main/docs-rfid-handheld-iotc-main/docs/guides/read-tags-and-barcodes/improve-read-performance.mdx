:::note[Applies to]

RFD40 and RFD90 handheld RFID readers. Other RFID-capable mobile computers may expose a smaller subset of these performance controls.

:::

**There is no single "maximum range" setting.** No profile, no power value, and no link profile turns a reader into a long-range reader on its own. A link-profile change is one part of read performance, and usually not the first part that matters.

Work the hierarchy below in order. Physical setup first, RF configuration second.

### Start From What You See {#start-from-the-symptom}

Zebra's RFD40/RFD90 read performance guide routes by symptom, and it is a faster way in than reading
the profiles one by one:

| What you observe | Where to go |
|---|---|
| Tags leave the read area before they are captured | A faster profile, and a faster link profile: [Choose a Performance Profile](/guides/read-tags-and-barcodes/choose-a-performance-profile) |
| The count stops before all known items are found | `CYCLE_COUNT`, which uses `SESSION_2` so each tag answers once |
| The same tags read repeatedly while others are missed | `CYCLE_COUNT` again: this is the session at work, not the power |
| Reads drop when another reader operates nearby | `DENSE_READERS`, or a Miller-4 or Miller-8 link profile |
| Tags near metal or liquid are inconsistent | The physical setup, below. Check the tag and its mounting first |
| Only the furthest tags are missed | Power and placement, below, before any RF setting |
| Battery does not last the shift | `OPTIMAL_BATTERY`, which lowers power and turns Dynamic Power Optimization on |
| Nothing specific is wrong | `BALANCED_PERFORMANCE` |

### The Order to Work In

```text
Difficult reads
    ↓
Check physical setup first
├── Tag type
├── Tag placement
├── Tag orientation
├── Metal / liquid
├── Obstructions
├── Reader position
└── Read distance
    ↓
Then consider RF configuration
├── Power
├── Session
├── DPO
└── RF mode / link profile
```

### Step 1 — Check the Physical Setup

Go through all seven factors before touching any RF setting. Change one at a time and re-read, so you know which one moved the result. [Test and Validate Performance](/guides/read-tags-and-barcodes/improve-read-performance#test-and-validate-performance) is the method.

:::caution[A missed tag does not mean "choose a slower link profile"]

"A tag was missed, so switch to a slower link profile" is the most common oversimplification in RF tuning, and it is wrong often enough to be worth naming. A missed tag is far more often a physical-setup problem — orientation, a metal or liquid surface, an obstruction, or simply distance — than a modulation problem. Changing the link profile first hides the real cause and costs throughput for nothing.

Rule out the physical setup, then treat the link profile as one candidate among the RF settings, not as the fix.

:::

### Step 2 — Then Consider RF Configuration

Four levers, in the order they are usually worth trying:

| Lever | What it controls | Tradeoff |
|---|---|---|
| **Power** (`transmitPower`) | Radio output power, declared from `0` to `300`; the unit is unresolved, see below | More power generally reaches further and energizes more tags, at the cost of battery and of interference with nearby readers. Capped by region, below. |
| **Session** (`session`) | The EPC Gen2 session, `SESSION_0`–`SESSION_3` | Governs how long a tag stays quiet after it is read. In typical Gen2 use, higher sessions suit several readers and large populations. See [How the Radio Reads Tags](/guides/core-concepts/how-the-radio-reads-tags). |
| **DPO** (`dynamicPower`) | Dynamic power optimization (boolean) | Lets the radio adjust transmit power during an inventory instead of holding it fixed. Whether `transmitPower` then acts as a ceiling or a starting point is not documented. |
| **RF mode / link profile** (`linkProfile`) | The air-interface encoding and backscatter link frequency, for example `M2_240K` for Miller-2 at 240 kHz | The contract describes faster profiles as reading more tags per second, and higher Miller orders as more robust with many readers and multipath. See [Advanced RF Configuration](/guides/read-tags-and-barcodes/configure-advanced-radio-settings#advanced-rf-configuration). |

Over MQTT these are the four fields of `advancedConfigurations`, set through [`set_operating_mode`](/api-reference/mqtt/ctrl/set-operating-mode) when `profiles` is `ADVANCED`. The mechanics — payload shape, ordering, error codes — are in [Configure the Operating Mode](/guides/read-tags-and-barcodes/configure-advanced-radio-settings#configure-the-operating-mode).

#### The Regulatory Ceiling {#the-regulatory-ceiling}

`transmitPower` must stay within the regulatory limit of the reader's region. The reader reports its regional maximum as `maxTxPowerSupported` from [`get_current_region`](/api-reference/mqtt/mgmt/get-current-region). No MQTT command changes the region; the reference page names 123RFID Desktop as the tool that sets it. Read the limit from the reader in front of you rather than copying a figure from any page, including this one.

**Confirm the `transmitPower` scale on your firmware before comparing the setting with the region ceiling.**

- `transmitPower` is declared in centi-dBm with a range of `0` to `300`. Confirm the power the setting applies on your reader.
- `maxTxPowerSupported` and `minTxPowerSupported` are declared in dBm. Both the field example and the worked region reply report a maximum of `30`.

:::caution[Confirm the setting scale before using the ceiling]
`maxTxPowerSupported` is reported in dBm. Do not copy its raw value into `transmitPower`; confirm the setting's scale on your firmware first.
:::

Establish the scale empirically, on the reader you are actually deploying:

1. Read the ceiling from *that* reader with [`get_current_region`](/api-reference/mqtt/mgmt/get-current-region). Whatever it reports is your maximum.
2. Set `transmitPower` with [`set_operating_mode`](/api-reference/mqtt/ctrl/set-operating-mode), then read it back with [`get_operating_mode`](/api-reference/mqtt/ctrl/get-operating-mode) to confirm the reader accepted the value you sent.
3. **Start low and increase.** Measure read range at each step (see [Test and Validate Performance](/guides/read-tags-and-barcodes/improve-read-performance#test-and-validate-performance)) and confirm the reader responds to the value before you trust it. Never assume a value means what it looks like.

:::warning[Read range is not a power measurement]

**Measuring read range establishes nothing about emitted power.** Range moves with the tag, its orientation, what it is mounted on, and everything else in the path; it cannot separate the power the radio applied from the rest of the link. Step 3 tells you the reader *responds* to the value you sent — it does not tell you how many dBm left the antenna, so it cannot settle a compliance question.

**Where regulatory margin matters, confirm the power actually applied — against Zebra's firmware documentation for your sled and firmware version, or by measuring it with an instrument.** No procedure on this page is a substitute for one of those two.

:::

Bands and limits per region: [RF Regions and Regulations](/resources/rf-regions-and-regulations).

### Two Things That Are Often Asked For and Are Not Levers Here

- **RSSI pre-filtering** — dropping a tag response below an RSSI threshold *at the radio*. `rssiFilter` is no part of this API: it belonged to a fixed-reader payload whose own documentation named the FX9600 as its only supported device, and it is **not available on RFD40/RFD90**. Do RSSI thresholding **application-side** instead, on the `peakRssi` value each tag record carries when the `RSSI` flag in `tagMetaDataToEnable` is on; see [`dataEVT`](/api-reference/mqtt/data/tag-data-event).
- **Gen2X extensions** — a set of Gen2-compatible, Impinj-chip features (Impinj TagFocus for session-1 flag persistence, Tag Quieting, Protected Mode, FastID for reading EPC and TID together, short-range read, Integra, tag authentication). These act at the tag / session-flag level, not the RF-power level. Zebra's source material presents Gen2X as a general Gen2/Impinj capability set and does **not** document a configurable RFD40/RFD90 `set_operating_mode` surface for it — confirm availability for your sled and firmware before designing around it.

### Before You Conclude Anything

Every change in this page has to be measured to count. Run it through [Test and Validate Performance](/guides/read-tags-and-barcodes/improve-read-performance#test-and-validate-performance): real work area, one change at a time, unique tags captured, missed tags, time to a stable count.

Zebra's guide puts the same discipline in three rules: test in the actual work area rather than at a
desk, change one setting at a time, and put a setting back before trying the next one if it did not
improve the result.

## Test and Validate Performance {#test-and-validate-performance}

:::note[Applies to]

RFD40 and RFD90 handheld RFID readers. Other RFID-capable mobile computers may expose a smaller subset of these performance controls.

:::

This is the **canonical method** for validating an RFID performance change. Every other page that suggests testing links here rather than restating the method.

A profile choice or an RF setting is a hypothesis. This page is how you find out whether it was right — and, just as important, how you avoid concluding something a repeat run would contradict.

#### How to Run the Test

1. **Test in the real work area.** A bench test tells you about the bench. Racking, metal, liquids, people, and nearby readers are part of the system under test.
2. **Keep the hardware and the environment constant.** Same reader, same tags, same operator, same route, same position. If the setup moves between runs, the result is about the setup, not the setting.
3. **Change one setting at a time.** Two changes in one run means neither is measured.
4. **Test repeatability.** Run the same test more than once. A number you cannot reproduce is not a result.
5. **Compare with nearby readers on and then off.** This is the only way to separate a coexistence problem from a configuration problem.

#### What to Measure

| Measure | Why it matters |
|---|---|
| **Unique tags captured** | The primary outcome for almost every deployment — did the reader find the items that were there? |
| **Missed tags** | Track them explicitly. A high unique count with a consistent set of misses is a different problem from a low count. |
| **Time to a stable count** | How long the operator has to keep scanning before the count stops moving. Speed the operator actually feels. |
| **Battery consumption** | A setting that meets the read target and does not last a shift has not met the requirement. |

#### Tuning Over MQTT

When the change is being made through [`set_operating_mode`](/api-reference/mqtt/ctrl/set-operating-mode) rather than in the app, the same method applies with a concrete loop:

1. Start from `BALANCED_PERFORMANCE`.
2. Measure read rate, unique-tag count, and battery against your target.
3. Move **one lever at a time** — typically `transmitPower`, then `session`, then `linkProfile` — and re-measure.
4. Lock in the resulting profile or `ADVANCED` configuration with [`set_operating_mode`](/api-reference/mqtt/ctrl/set-operating-mode). Inventory must be stopped first, or the command returns code `11`.

Stopping and starting the radio is covered in [Start and Stop Inventory](/guides/read-tags-and-barcodes/start-and-stop-inventory); the payload shape is in [Configure the Operating Mode](/guides/read-tags-and-barcodes/configure-advanced-radio-settings#configure-the-operating-mode).

:::note[Recommended values are not published]

The levers on these pages come from the `set_operating_mode` contract and the supplied performance material. **Recommended values for a given environment are not published.** Treat this section as the method and the knobs, not as a settings table — your measurements decide the values.

:::

#### When the Result Is Still Wrong

If a validated test still misses the requirement, go back one level rather than reaching further into the radio:

- Weak, distant, or awkward tags → [Improve Read Performance](/guides/read-tags-and-barcodes/improve-read-performance), physical setup first.
- The wrong objective entirely → [Choose a Performance Profile](/guides/read-tags-and-barcodes/choose-a-performance-profile).
- Only then → [Advanced RF Configuration](/guides/read-tags-and-barcodes/configure-advanced-radio-settings#advanced-rf-configuration).
