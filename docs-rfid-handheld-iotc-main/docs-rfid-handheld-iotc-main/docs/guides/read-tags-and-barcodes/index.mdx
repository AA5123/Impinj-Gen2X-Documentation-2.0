These pages cover what the reader does on the air: starting and stopping an inventory, scanning barcodes, tuning the radio, deciding which reads are reported and what each record carries, and reading and writing tag memory.

Almost everything here is part of one object, the operating mode, sent with [`set_operating_mode`](/api-reference/mqtt/ctrl/set-operating-mode) and read back with [`get_operating_mode`](/api-reference/mqtt/ctrl/get-operating-mode). Two rules apply to all of it:

- **Configure while the radio is idle.** The reader refuses `set_operating_mode` with code `11` during an inventory.
- **Re-apply after a restart.** The operating mode is lost on reboot, and the reader returns to its default mode.

Starting and stopping is separate: [`control_operation`](/api-reference/mqtt/ctrl/control-operation) does it, for RFID and for the barcode scanner. Post-filters, which decide what each data endpoint reports, are set with [`set_post_filter`](/api-reference/mqtt/ctrl/set-post-filter). How the radio finds tags is explained in [How the Radio Reads Tags](/guides/core-concepts/how-the-radio-reads-tags), and how reads become messages in [The Tag Data Stream](/guides/core-concepts/the-tag-data-stream).
