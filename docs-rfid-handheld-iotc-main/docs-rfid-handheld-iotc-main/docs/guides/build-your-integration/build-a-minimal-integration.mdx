## Build the App: From Connect to Unique Tags

By the end of these five steps you have one runnable script that connects, subscribes, starts inventory, ingests tag reads, and stops cleanly.

### Step 1: Connect to the Broker

Create `first_tag_app.py`. Set your connection details, then connect a Paho client and start its network loop in the background:

```python
import json, time
import paho.mqtt.client as mqtt

TENANT = "zebra"
SERIAL = "RFD40-24190525100255"          # your reader's serial number
BROKER, PORT = "broker.example.com", 1883

def on_connect(client, userdata, flags, reason_code, properties=None):
    print("connected" if reason_code == 0 else f"connect failed: {reason_code}")

client = mqtt.Client(mqtt.CallbackAPIVersion.VERSION2, client_id="first-tag-app")
client.on_connect = on_connect
client.connect(BROKER, PORT, keepalive=60)
client.loop_start()
time.sleep(1)
```

**You should see** `connected` printed. If not, the broker host/port is wrong or unreachable — the same path you verified in [Prepare the Network and Broker](/guides/quick-start#prepare).

### Step 2: Subscribe to the Tag Stream and Command Responses

This app uses the `CTRL` and `DATA1` endpoints you added in the [Quick Start: Read Your First Tag](/guides/quick-start#first-tag-reads). The reader publishes `dataEVT` tag data on the `DATA1` endpoint's tag-data topic and answers your commands on the `CTRL` response topic. Every topic is `<tenant>/<middle segment>/<serial>` (see [Endpoints, Topics, and Channels](/guides/core-concepts/endpoints-topics-and-channels)). Subscribe to both inside `on_connect`, so the subscriptions are renewed after a reconnect:

```python
CMD_TOPIC  = f"{TENANT}/CTRL/clients/cmnd/{SERIAL}"   # we publish commands here
RESP_TOPIC = f"{TENANT}/CTRL/clients/resp/{SERIAL}"   # the reader answers here
DATA_TOPIC = f"{TENANT}/DATA/clients/data1event/{SERIAL}"  # dataEVT tag reads land here

def on_connect(client, userdata, flags, reason_code, properties=None):
    if reason_code != 0:
        print(f"connect failed: {reason_code}")
        return
    client.subscribe([(RESP_TOPIC, 1), (DATA_TOPIC, 0)])
    print("connected and subscribed")
```

**You should see** `connected and subscribed`. Nothing flows yet — the radio is idle until Step 3.

### Step 3: Start Inventory from Your Code

Send [`control_operation`](/api-reference/mqtt/ctrl/control-operation) `START` on the CTRL command topic. The payload key is `ctrlOprPayload`; `controlType` and `operation` are **uppercase** <SchemaBadge>enum</SchemaBadge>s:

```python
def control(op, request_id):
    client.publish(CMD_TOPIC, json.dumps({
        "command": "control_operation",
        "requestId": request_id,
        "ctrlOprPayload": {"controlType": "RFID", "operation": op},
    }))

control("START", "app-start-001")
```

**You should see** a command response arrive on `RESP_TOPIC` with `response.code` `0` (you will print it in Step 4). Code `11` means an inventory is already running — send `STOP` first. The codes are explained in [Start and Stop Inventory](/guides/read-tags-and-barcodes/start-and-stop-inventory), and the general rules in [Send Commands and Handle Responses](/guides/build-your-integration/send-commands-and-handle-responses).

### Step 4: Turn `dataEVT` into a Live Unique-Tag Set

`dataEVT` is an **event**, not a command response: it has `type`, `timestamp`, and `data.tagData[]`, with no `requestId`/`response` envelope. Each message can carry several tag records, and the same tag can appear more than once. Each record carries `EPCid` (the tag's identity) and, when enabled, fields such as `peakRssi` and `seenCount`. Route messages by topic and deduplicate by `EPCid`:

```python
seen = {}   # EPCid -> times seen

def on_message(client, userdata, msg):
    payload = json.loads(msg.payload)
    if "/data1event/" in msg.topic:                 # a dataEVT tag-read event
        for tag in payload.get("data", {}).get("tagData", []):
            epc = tag.get("EPCid")
            if not epc:
                continue
            if epc not in seen:
                rssi = tag.get("peakRssi")
                print(f"new tag {epc}" + (f"  rssi={rssi} dBm" if rssi is not None else ""))
            seen[epc] = seen.get(epc, 0) + 1
    elif "/CTRL/clients/resp/" in msg.topic:        # a command response
        print(f"{payload.get('command')} -> code {payload.get('response', {}).get('code')}")

client.on_message = on_message
```

**You should see** a `new tag <EPC>` line the first time each tag is reported, with repeats counted in `seen`. This counts reports, not reads: one report can stand for several reads, which the record's `seenCount` gives when it is enabled. The field reference is [`dataEVT`](/api-reference/mqtt/data/tag-data-event).

### Step 5: Stop Cleanly and Summarize

Read for a fixed window (or until you press Ctrl-C), send `STOP`, then report what the application captured:

```python
print("inventory started — present some tags (Ctrl-C to stop)")
try:
    time.sleep(15)                 # read for 15 seconds
except KeyboardInterrupt:
    pass

control("STOP", "app-stop-001")
time.sleep(1)

print(f"\ndone — {len(seen)} unique tag(s):")
for epc, count in sorted(seen.items()):
    print(f"  {epc}  (seen {count}x)")

client.loop_stop()
client.disconnect()
```

**You should see** a `control_operation -> code 0` line (or `12`, which just means the radio was already idle — harmless), then a summary listing each unique EPC and how many reports were received for it.

### The Complete App

```python
import json, time
import paho.mqtt.client as mqtt

TENANT = "zebra"
SERIAL = "RFD40-24190525100255"          # your reader's serial number
BROKER, PORT = "broker.example.com", 1883

CMD_TOPIC  = f"{TENANT}/CTRL/clients/cmnd/{SERIAL}"
RESP_TOPIC = f"{TENANT}/CTRL/clients/resp/{SERIAL}"
DATA_TOPIC = f"{TENANT}/DATA/clients/data1event/{SERIAL}"

seen = {}   # EPCid -> times seen

def on_connect(client, userdata, flags, reason_code, properties=None):
    if reason_code != 0:
        print(f"connect failed: {reason_code}")
        return
    client.subscribe([(RESP_TOPIC, 1), (DATA_TOPIC, 0)])
    print("connected and subscribed")

def on_message(client, userdata, msg):
    payload = json.loads(msg.payload)
    if "/data1event/" in msg.topic:
        for tag in payload.get("data", {}).get("tagData", []):
            epc = tag.get("EPCid")
            if not epc:
                continue
            if epc not in seen:
                rssi = tag.get("peakRssi")
                print(f"new tag {epc}" + (f"  rssi={rssi} dBm" if rssi is not None else ""))
            seen[epc] = seen.get(epc, 0) + 1
    elif "/CTRL/clients/resp/" in msg.topic:
        print(f"{payload.get('command')} -> code {payload.get('response', {}).get('code')}")

def control(op, request_id):
    client.publish(CMD_TOPIC, json.dumps({
        "command": "control_operation",
        "requestId": request_id,
        "ctrlOprPayload": {"controlType": "RFID", "operation": op},
    }))

client = mqtt.Client(mqtt.CallbackAPIVersion.VERSION2, client_id="first-tag-app")
client.on_connect = on_connect
client.on_message = on_message
client.connect(BROKER, PORT, keepalive=60)
client.loop_start()
time.sleep(1)

control("START", "app-start-001")
print("inventory started — present some tags (Ctrl-C to stop)")
try:
    time.sleep(15)
except KeyboardInterrupt:
    pass

control("STOP", "app-stop-001")
time.sleep(1)

print(f"\ndone — {len(seen)} unique tag(s):")
for epc, count in sorted(seen.items()):
    print(f"  {epc}  (seen {count}x)")

client.loop_stop()
client.disconnect()
```

### Recap

You wrote an application that connects to the broker, subscribes to the `DATA1` tag-data topic, starts and stops inventory through the `CTRL` endpoint, and turns `dataEVT` into an in-memory set of unique tags. That ingest-and-deduplicate loop is the core of every IOTC application; from here you swap the `print` and the `seen` dict for your own pipeline — a database write, an HTTP post, a dashboard update.

### Did Not Work? {#didnt-work}

- **`connected` but no `new tag` lines.** Confirm `START` returned code `0`, that tags are in range, and that the profile is not `FAST_READ`, whose behaviour with tag data is not settled. See [Start and Stop Inventory](/guides/read-tags-and-barcodes/start-and-stop-inventory).
- **`new tag` lines never appear but a CTRL response does.** The reader is not publishing tag data on `DATA_TOPIC`. Confirm with [`get_endpoint_config`](/api-reference/mqtt/mgmt/get-endpoint-config) that the `DATA1` endpoint is active and has its tag-data topic in the **second** publish-topic position; with a single publish topic it streams nothing. See [Where Tag Data Is Published](/guides/core-concepts/the-tag-data-stream#topic-routing).
- **`TypeError` on `mqtt.Client(...)`.** You are on paho-mqtt 1.x. Upgrade (`pip install -U paho-mqtt`) or drop the `CallbackAPIVersion.VERSION2` argument and use the 1.x callback signatures.
