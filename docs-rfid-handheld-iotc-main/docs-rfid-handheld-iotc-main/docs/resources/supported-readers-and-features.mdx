## Reader Capability Matrix {#capability-matrix}

Check your reader before you plan an integration. The MQTT API runs in the reader’s own firmware and reaches the broker over the reader’s own network connection: Wi-Fi, or Ethernet through a communication cradle. From Zebra’s spec sheets, product guides and release notes for each model, and the IoT Connector’s API owners:

| | RFD40 Standard | RFD40 Premium | RFD40 Premium Plus | RFD40-M Premium Plus | RFD90 (RFD9030, RFD9090) |
|---|---|---|---|---|---|
| **IoT Connector and MQTT API** | Yes, through a communication cradle | Yes | Yes | Yes | Yes |
| **Wi-Fi** | None listed | Wi-Fi 6, IEEE 802.11ax, 2×2 | Wi-Fi 6, IEEE 802.11ax, 2×2 | Wi-Fi 6, IEEE 802.11ax, 2×2 | Wi-Fi 6, IEEE 802.11ax, 2×2 |
| **Bluetooth** | None listed | Bluetooth 5.3 | Bluetooth 5.3 | Bluetooth 5.3 | Bluetooth 5.3 |
| **Host connection** | eConnex, USB-C cable, USB cable cup | eConnex, Bluetooth, USB-C cable, USB cable cup | eConnex, Bluetooth, USB-C cable, USB cable cup | eConnex, Bluetooth, USB-C cable, USB cable cup | eConnex, Bluetooth, USB cable cup |
| **Remote management** | Through a multi-slot Ethernet cradle | Wi-Fi 6, Ethernet cradles, or the attached host device | Wi-Fi 6, Ethernet cradles, or the attached host device | Wi-Fi 6, Ethernet cradles, or the attached host device | Wi-Fi 6, Ethernet cradles, or the attached host device |
| **Barcode imager** | None: UHF RFID only | None | SE4100 | SE4100 | SE4750MR or SE4850, by configuration |
| **`model` in `get_version`** | Not specified in the available sources | `RFD40` | `RFD40` | Not specified in the available sources; the model name and `sku` identify it | `RFD90` |
| **Minimum firmware for the IoT Connector** | `SAAFKS00-009-R00` or later recommended for the communication cradle | `SAAFKS00-008-R00` for `MDM` | `SAAFKS00-008-R00` for `MDM` | `SAAFKS00-012-R00`; full support from `SAAFKS00-013-R02` | `SAAFKS00-008-R00` for `MDM` |

- **The RFD40-M Premium Plus runs the IoT Connector.** It is based on the RFD40 Premium Plus, with a different antenna, and has the same Wi-Fi 6 radio. [`get_version`](/api-reference/mqtt/mgmt/get-version) identifies it by its model name and `sku`; the exact values are not specified in the available sources. Full support for it, in `SAAFKS00-013-R02`, also needs the latest 123RFID Desktop.
- **The RFD40 Standard runs the IoT Connector through a communication cradle.** It has no Wi-Fi radio. Its IoT Connector is already active: once its endpoints are configured and it is docked, the cradle gives it a network connection and the IoT Connector connects to the broker. Zebra’s release notes record a known, intermittent reset when an IoT connection is established through the communication cradle. The Standard also works as a tethered reader through an attached mobile computer or PC.
- **Barcode data needs an imager.** On a reader without one, `SCANNER` operations and barcode data in [`dataEVT`](/api-reference/mqtt/data/tag-data-event) cannot occur.
- **`model` has two values.** The contract’s model vocabulary is `RFD40` and `RFD90`. [`get_version`](/api-reference/mqtt/mgmt/get-version) also reports `sku`, which encodes the model, configuration and regulatory region, and the firmware versions.

## Features {#features}

Every reader that runs the IoT Connector exposes the same MQTT API: 20 commands and 4 events. Two things vary by reader:

| Feature | What varies | Readers |
|---|---|---|
| Barcode scanning | Needs a barcode imager | RFD40 Premium Plus, RFD40-M Premium Plus and RFD90. See the matrix above |
| Wi-Fi | Needs a Wi-Fi interface | Every reader except the RFD40 Standard, which reaches the broker through a communication cradle. A reader without Wi-Fi returns code `20` to `set_wifi` |

## Minimum Firmware {#minimum-firmware}

The IoT Connector’s API owners give the minimum firmware by endpoint type. `SAAFKS00-008-R00` and later support the generic `MDM` endpoint type. The Quick Start and the guides use an `MDM` endpoint, so they need `SAAFKS00-008-R00` or later.

Parts of the MQTT API documented here arrived in later releases. The [firmware history](/api-reference/mqtt/changelog#firmware-history) lists them, for example content-based certificate install and IOTC API version `1.21` in `SAAFKS00-013-R02`. Two readers have conditions of their own:

- **RFD40-M Premium Plus.** The firmware history records support for it from `SAAFKS00-012-R00`, and Zebra’s release notes list full support in `SAAFKS00-013-R02`.
- **RFD40 Standard.** It connects only through a communication cradle, and Zebra’s release notes recommend `SAAFKS00-009-R00` or later for the IoT Connector with the cradle.

The latest firmware recorded in this documentation is `SAAFKS00-013-R05`. Replies carry an `apiVersion`, and the contract's examples show `V1.1` and `V1.21` among others; a complete firmware-to-API-version mapping is not specified in the available sources. The firmware history records API `1.21` in `SAAFKS00-013-R02`. See [Versioning and Compatibility](/api-reference/mqtt/versioning-and-deprecation-policy).
