The reader starts every connection it makes: nothing connects in to the reader. Allow these outbound connections from the reader's network.

| Connection | Destination | Port | When |
|---|---|---|---|
| MQTT, plain | The broker in each endpoint's `url` | The endpoint's `port`, conventionally `1883` | Always, for plain MQTT endpoints |
| MQTT over TLS | The broker in each endpoint's `url` | The endpoint's `port`, conventionally `8883` | Always, for `MQTT_TLS` endpoints |
| Firmware download | The server in `set_os`'s `url`, HTTP or HTTPS | The URL's port | During a firmware update |
| Certificate download | The servers in `install_certificate`'s `url` entries | Their ports | When `certSource` is `HTTP` |
| Address assignment | The network's DHCP server | DHCP | When `enableDhcp` is `true` |
| Name resolution | The DNS server in the Wi-Fi configuration | DNS | When an endpoint's `url` or a download URL is a host name |

Every reader connection to the broker is TCP. The reader does not cross-check an endpoint's `protocol` and `port`, so the firewall rule must match the port you configure, not only the convention.

The reader also reports clock synchronization, as `ntp.offset` in [`get_status`](/api-reference/mqtt/mgmt/get-status), but the available sources do not describe how the reader is configured to reach a time server. Certificate validity depends on the reader's clock.

## Your Applications {#applications}

Your applications also connect outbound, to the same broker, on the ports your broker offers. They never connect to the reader directly.

## Check the Path {#check}

From a computer on the reader's network:

```bash
nc -vz <broker-host> 8883
```

A successful connection shows the path to the broker is open. See [Network and Connectivity](/guides/diagnose-and-recover/diagnose-by-system-area/network-and-connectivity).
