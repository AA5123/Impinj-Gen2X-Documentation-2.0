Where to go for help, in the order that resolves fastest.

## Diagnose It Here First

Most reported problems on this product are covered by the symptom-first surface, and it
is quicker than raising a case:

- 🔧 [Diagnose and Recover](/guides/diagnose-and-recover) — start from what you are
  seeing, not from what you think is broken.
- 🔧 [Recovery playbooks](/guides/diagnose-and-recover/recovery-playbooks) — step-by-step
  recovery for the common failure paths.
- ❓ [FAQs](/resources/faq) — general, connectivity, compatibility, RFID and fleet.

## Check the Reference

If the behavior disagrees with what you expected, the command's own page is the
authority on its payload and its response codes:

- 📕 [MQTT API](/api-reference/mqtt) — the handheld RFD40 / RFD90 command and event
  reference.

## Contact Zebra

| Channel | Use it for |
|---|---|
| [Zebra Support and Downloads](https://www.zebra.com/us/en/support-downloads.html) | Firmware downloads, warranty, repair, and opening a support case |
| [Zebra Developer Portal](https://developer.zebra.com) | SDKs, developer documentation, and integration guidance |
| [Zebra Developer Community](https://developer.zebra.com/community) | Questions answered by Zebra engineers and other developers |

## Before You Open a Case

Collect the evidence first. A case that arrives with the reader's identity, the failing
request and the reply already attached turns a multi-day thread into a single exchange —
[Escalate to Support](/guides/diagnose-and-recover/escalate-to-support)
lists what to capture, which command it comes from, and what to redact before you attach it.
