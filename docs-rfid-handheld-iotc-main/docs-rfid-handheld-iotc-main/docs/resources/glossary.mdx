The terms this documentation uses, with what each one means and, where it matters, what it does not mean. For exact field names, values and codes, the [MQTT API](/api-reference/mqtt) reference is authoritative; for the numbers, see [Limits](/api-reference/mqtt/limits) and [Response Codes](/api-reference/mqtt/response-codes).

### Terms

| Term | Definition |
|---|---|
| **123RFID Desktop** | A Zebra Windows application that connects to a reader over USB-C and sets what MQTT cannot: the regulatory region, the first Wi-Fi profile and the first MQTT endpoint. See [Setup Tools](/resources/setup-tools). |
| **Access operation** | An operation the reader runs against every tag it reads during an inventory: `READ`, `WRITE`, `ACCESS`, `LOCK` or `KILL`. Configured in `accessOperations` of the operating mode. |
| **`ADVANCED`** | The operating-mode profile in which you set the link profile, transmit power, session and dynamic power yourself, in `advancedConfigurations`. |
| **`alerts`** | The event that reports a condition change. Its `id` is `BATTERY`, `FILE_DOWNLOAD`, `FIRMWARE_UPDATE`, `NETWORK_EVENT` or `POWER`; its `priority` is `CRITICAL`, `HIGH` or `LOW`; its `state` is `SET`, `CLEAR` or `ONESHOT`. See [`alerts`](/api-reference/mqtt/events/alerts-event). |
| **Asynchronous command** | A command that replies before its work is done: `set_os`, `install_certificate` and `reboot`. Their reply, code `1`, means accepted, not succeeded. |
| **Channel** | The route one kind of message takes: a topic, and the endpoint slot that feeds it. Not the `channel` field of a tag record, which is an opaque radio channel index. |
| **Command** | A message your application publishes to a reader's command topic, naming the operation in `command`. |
| **`CTRL`** | The endpoint type for RFID control commands and their replies. |
| **`ctrlOprPayload`** | The payload object of [`control_operation`](/api-reference/mqtt/ctrl/control-operation). |
| **`DATA1`, `DATA2`** | The endpoint types for tag data. `DATA2` is currently not supported, so `DATA1` is the data endpoint to use. |
| **`dataEVT`** | The event that carries tag and barcode reads, in batches. A whole message is limited to 6144 bytes, not to a number of records. See [`dataEVT`](/api-reference/mqtt/data/tag-data-event). |
| **Endpoint** | A named MQTT connection configuration stored on the reader: the broker, security and topics for one class of traffic. |
| **`epConfig`** | The payload object of [`config_endpoint`](/api-reference/mqtt/mgmt/config-endpoint). |
| **`epType`** | The endpoint type: `MGMT`, `MGMT_EVT`, `CTRL`, `DATA1`, `DATA2`, `MDM`. `DATA2` is currently not supported. |
| **`eventConfiguration`** | The payload object of [`config_events`](/api-reference/mqtt/mgmt/config-events). An endpoint's read-back also carries a per-endpoint block of the same name; the contract does not say which of the two wins. |
| **`FAST_READ`** | An operating-mode profile whose status is not settled: one source says it is not supported, another that tag-data events are not supported with it. |
| **`heartBeatEVT`** | The periodic heartbeat, and the primary liveness signal. Its payload carries `eventName: "heartbeat"`. The interval is at most 65,535 seconds. |
| **Inventory** | A run of the RFID radio reading tags, started and stopped with `control_operation` or the trigger. |
| **IoT Connector** | The firmware on the reader that provides the MQTT API. |
| **Last Will** | The `DISCONNECTED` form of `mqttConnEVT`, registered with the broker when the reader connects and published by the broker if the connection ends without a clean disconnect. It carries no timestamp. |
| **Liveness signal** | Evidence that a reader, its session and the path to your application work. `heartBeatEVT` is the primary one. |
| **`MDM`** | An endpoint type: a mobile-device-management form of the management endpoint. Readers are commonly bootstrapped with an MDM endpoint. |
| **`MGMT`, `MGMT_EVT`** | The endpoint types for management commands and replies, and for management events on a separate endpoint. |
| **MQTT API** | The interface the IoT Connector provides: 20 commands and 4 events, defined by an AsyncAPI contract. |
| **`mqttConnEVT`** | The connection-state event. The reader publishes `CONNECTED` when a session starts; the Last Will is its `DISCONNECTED` form. Its `timestamp` is optional, and whether it is retained is not settled. |
| **Operating mode** | The single object that configures the RFID radio: profile, advanced settings, access operations, start and stop conditions, query, select and metadata flags. Lost on reboot. |
| **`operatingMode`** | The payload object of [`set_operating_mode`](/api-reference/mqtt/ctrl/set-operating-mode). It wraps `operatingModes`. |
| **Performance profile** | A named radio configuration, the `profiles` value of the operating mode, such as `BALANCED_PERFORMANCE`. |
| **Post filter** | A rule that decides which read tags a data endpoint reports, set with `set_post_filter` for `DATA_EP1`, the `DATA1` endpoint. (`DATA_EP2` targets `DATA2`, which is currently not supported.) |
| **`postFilterPayload`** | The payload object of [`set_post_filter`](/api-reference/mqtt/ctrl/set-post-filter). |
| **Pre-filter (`select`)** | A Gen2 Select filter applied on the air before the inventory round. Up to 32, in `select` of the operating mode. |
| **Reader** | An RFD40 or RFD90 handheld RFID reader: the hardware and its state. |
| **`reportFilter` duration** | No `reportFilter` setting is declared in the current contract. The reference describes per-read and aggregated reporting shapes. |
| **Request ID (`requestId`)** | The identifier your application puts in a command and the reader echoes in its reply: the only way to pair them. The reader does not use it to detect repeats. |
| **Response (reply)** | The message a reader publishes for each command, with `command`, `requestId`, `apiVersion` and `response`. |
| **Session (Gen2)** | The EPC Gen2 session, `SESSION_0` to `SESSION_3`, that governs how long a tag stays quiet after it is read. |
| **Sled** | Another word for the reader, from the way it attaches to a mobile computer. |
| **Status code (response code)** | The integer in `response.code` that states a command's outcome. See [Response Codes](/api-reference/mqtt/response-codes). |
| **Tag-data reconciliation** | Comparing received tag data with the `inventoryStatus` counters in `heartBeatEVT`. It can reveal a discrepancy; it cannot prove capture is complete. |
| **Tenant ID (`tenantId`)** | The first segment of every topic, set per endpoint, at most 48 characters. The reader adds it itself; never write it into a `topic`. Its case is not normalized. |
| **Topic** | The MQTT address of a message: `<tenantId>/<middle segment>/<deviceSerialNumber>`. |
| **Topic slot** | The position of an entry in an endpoint's `publishTopics`, which decides what the reader publishes there: `[0]` replies, `[1]` events or tag data, `[2]` the Last Will and `mqttConnEVT`. |
| **`verificationType`** | How far the reader checks a TLS server's certificate: `VERIFY_HOST_AND_PEER` checks the certificate chain and host name; `VERIFY_NONE` checks nothing and must not be used in production. |
